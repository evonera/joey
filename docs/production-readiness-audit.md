## Follow-up findings and fixes

- **Publishing races and duplicate prevention:** preserve canonical webhook results when they arrive before the create-post HTTP response; save remote mappings under row locks. Already accepted posts are reconciled without resubmission. Ambiguous attempts require verification rather than an unsafe retry. Explicit “Publish Early” works while scheduled workers still respect future dates.
- **Review queue:** editing, approval, rejection and deletion cannot reset publishing posts or uncertain/accepted publication attempts. Bulk actions reuse the same guards. Theme posts in progress now display Publishing, with accurate action feedback.
- **Workspace isolation:** Zernio analytics and inbox backfills use the workspace profile and filter account ownership. Shared or ambiguous webhook account mappings are rejected. OAuth uses a workspace-bound nonce and dedicated provider profile; connection sync preserves local references.
- **Webhook durability:** failed and abandoned deliveries are recovered with backoff, transaction locks, a bounded batch and eight-attempt limit. Millisecond timestamps round-trip through PostgreSQL so the delivery fence matches correctly. The older worker no longer consumes these payloads.
- **Calendar:** include Theme Studio packages and published posts; avoid duplicates, support clicking historical records, and open the correct editor. Only eligible scheduled drafts can move, enforced atomically. Invalid views fall back to Month; selecting a date passes it to Compose.
- **Media correctness:** remote images are fetched explicitly through the existing bounded SSRF-safe client before PNG rendering. TikTok video payloads exclude poster PNGs; approved captions are preserved. Sample Day is explicitly illustrative and no longer claims fake source verification.
- **Renderer security:** reproduced native renderer access to local image paths. Validate resource references before the native constructor, reject inline/local resources and XML declarations, bound SVG dimensions, and escape brand fonts in video templates. This function accepts generated template SVG, not arbitrary uploaded SVG documents.
- **Flow templates:** added Instagram Theme Image and TikTok Video Caption templates with explicit setup requirements. Create Draft supports nine platforms, preserves arrays of media URLs, checks active account ownership/platform, pins unambiguous account targets and respects run fencing. The reply-suggestion template accurately describes its notification-only output. Flow node settings now show named publishing accounts filtered by platform, associated form labels, schema setup hints and a connection link for empty workspaces. Built-in catalog corrections now reach existing installations without changing installed flows; installation counters update atomically.
- **Provider settings:** disabled workspace keys cannot silently spend a server key, including in image generation. Chat model availability respects disabled providers. Gemini 3.1 uses the provider's preview model identifier. Voice/schedule settings validate times, time zones, days and account ownership.
- **Billing UI and catalog:** installed the official Dodo BillingSDK pricing-table source and adapted it to Joey's monthly workspace plans. Creator, Pro and Agency test catalog descriptions now match Joey's enforced 10/100/500-page and 12/24/48-slot limits. Browser acceptance exposed that a null-status session could outlive its hosted URL; checkout reuse is now limited to a recent ten-minute window so expired links are replaced. Dodo's official India success test card activated Creator without a real charge.
- **Zernio credential lifecycle:** Settings now discovers the workspace's encrypted Zernio key, validates replacements with Zernio before storing them, and atomically clears the workspace profile/deactivates linked accounts when the key is removed. The current key validates against Zernio; LinkedIn reaches the provider OAuth screen. X correctly returns Zernio's payment-method requirement.
- **Optional integrations:** when Composio is not configured, Settings now shows a user-facing disabled state instead of exposing an internal environment-variable instruction. Zernio, flow integrations and webhooks remain usable.
- **Navigation:** defer rich chat message rendering and the closed side panel; parallelize Theme Studio detail reads. A repeatable local cold AI Chat measurement fell from 1,140,379 to 624,028 transferred script bytes (~45%). Local navigation timings include browser automation overhead and are not production Core Web Vitals.

## Database rollout

Historical migrations 0015 and 0031 were repaired because their original SQL cannot replay on a fresh database. The Drizzle runner skips already journaled migrations, so these repairs are intended for fresh installations; they do not alter deployed tables by themselves. New schema changes are appended as 0038 (workspace billing subscription), 0039 (AI usage ledger), 0040 (reusable checkout), 0041 (dedicated Zernio workspace profile), 0042 (bounded webhook recovery attempts), 0043–0045 (render jobs, timed-transcript cache and transcription cost), 0046 (atomic usage reservations) and 0047 (checkout plan fencing).

For an installation previously managed with `drizzle-kit push`, first back up the database and create an isolated Neon branch. Compare its complete schema with a fresh migration replay. Establish a reviewed baseline journal only after matching schema and data invariants. Do not copy a journal blindly or run historical SQL over an existing schema. The new command intentionally stops on an unjournaled existing schema. Apply and verify new migrations in that branch before production.

Use the transactional Neon driver (`DATABASE_PROVIDER=neon`) for deployment. Numerous workflows require transactions and locks; the legacy `neon-http` path cannot provide the same guarantees.
